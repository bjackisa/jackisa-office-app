## Session 6b — root causes found
- **SMTP fixed**: jackisa.com stores `smtp_password` AES-128-ECB-encrypted with the
  FIXED key `mysecretkey1234` (hard-coded in functions_one.php PT_SendMessage), not
  `$siteEncryptKey`. Decrypted it into lic config. Host `my.mailbux.com:587` user
  `info@jackisa.com`, TLS/STARTTLS. lic mail now sends.
- **lic route bug**: `/api/v1/office-license/status` was registered GET-only but the
  office client POSTs it -> 404. Changed to `any()`. Also `plans` is GET-only and the
  office client fetches it GET (fine).
- **office -> lic peer sync is broken because the office app signs with an EMPTY
  secret** — `LIC_OFFICE_SECRET`/`LIC_API_KEY` are unset in Vercel. Proof: the captured
  signature over `{"tenant_id":"0000..."}` equals HMAC-SHA256 with an empty key.
  Fix = set one Vercel env var: `LIC_OFFICE_SECRET=<lic peers.office.shared_secret>`.
- lic `peers.office` now has a primary `shared_secret` PLUS a `shared_secrets` list so
  rotation is zero-downtime (Crypto::verifyPeer tries all). Office peer.ts inbound
  verifier also tries LIC_OFFICE_SECRET then LIC_API_KEY.

## Session 6 — auth flow + feature gating (this session)

### Business-type gating was dead because nothing wrote `companies.kind`
`companies.kind` (varchar, default 'company') drives `lib/lic/features.ts` company-kind
gating, but no code path ever set it — signup, register/complete and settings all omitted
it. Fixed end to end: register page now has a "What are you setting up?" selector
(company|institution|ngo|cooperative|individual), `companyKind` flows through
localStorage `pendingRegistration` + `/api/signup-intent`, `/api/register/complete`
validates and inserts `kind`, and settings/company can edit it.

### Role-based gating had no UI
`company_role_features` (company_role_id, feature_slug, enabled) existed in
`scripts/licensing-and-platform-v1.sql` but nothing read or wrote it. `app/app/settings/roles`
only listed roles. Added an expandable per-role feature-grant editor that upserts
`company_role_features` (onConflict company_role_id,feature_slug) using the `FEATURES`
registry from `lib/lic/features.ts`.

### Paid licence never reached the app
lic issues/renews the licence after a settled payment (PaymentService::fulfill), but the
office never pulled the new certificate, so a paid workspace stayed locked. Added
`lib/lic/mirror.ts` (`mirrorLicenseFromHub`) — one shared mirror into `platform_licenses`
(handles both a `certificate.payload` and a bare `license` shape). `app/api/lic/license`
now uses it for issue/trial/renew; `app/api/lic/payments` status=paid now pulls
`lic.licenseStatus(companyId)` and re-mirrors so the app unlocks without a reload.

### Join/invite flow already existed and is fine
`/auth/join` + `app/api/companies/members` (create_invite/list_invites/revoke_invite/
request_join) + `app/api/students/link`. Invite link `?invite=<token>` / `?student=<token>`.
No change needed there.

### Still blocking lic integration
`LIC_OFFICE_SECRET` must be set in Vercel = lic `peers.office.shared_secret`. Without it
the office signs office→lic with an empty secret. Only the user can set it.
