# 2026-11-03 — maintenance mode gate

## What was built
The office app now has a hard maintenance gate. `MAINTENANCE_MODE=on` closes the
whole site: `proxy.ts` rewrites every HTML request to `public/maintenance.html`
(the retired-app page the user supplied) and returns 503 for `/api/*` and for
non-HTML fetches (RSC/prefetch). No skip buttons, no exceptions.

Only a platform super-admin can pass, and only after proving **both**:
1. knowledge of `MAINTENANCE_BYPASS_KEY`, and
2. ownership of a `super_admin` account (email+password, or a Supabase bearer).

They exchange that for a signed httpOnly cookie (`jo_maint_bypass`) at
`POST /api/maintenance/unlock`; `proxy.ts` validates it on every request. The
unlinked form lives at `/unlock.html`. `POST /api/maintenance/lock` clears it.

Files: `proxy.ts`, `lib/maintenance.ts`, `app/api/maintenance/{unlock,lock}/route.ts`,
`public/maintenance.html`, `public/unlock.html`.

## Next.js 16 gotcha (costly)
**`middleware.ts` is renamed to `proxy.ts` in Next.js 16** and the exported
function is `proxy` (not `middleware`). `middleware.ts` still runs but warns and
is deprecated. The proxy runs on the **Node.js runtime** and throws if a
`runtime` export is set. `export const config = { matcher }` is unchanged.

## Why the Lottie runtime is inlined
The app's CSP (`next.config.mjs`) is `script-src 'self' 'unsafe-inline'`, so the
template's `<script src="https://cdnjs.cloudflare.com/.../lottie.min.js">` is
blocked. The 305 KB runtime is inlined into `public/maintenance.html` instead.
(No `</script>`/`<script`/`<!--` in the file, so inlining is safe.)

## Vercel env workflow (worked)
`POST /v10/projects/{id}/env?teamId=…&upsert=true` with
`{key,value,type:'encrypted',target:['production','preview','development']}` →
201. **Env vars are captured when a build is created**, so set them *before* the
deploy that needs them, or force a redeploy:
`POST /v13/deployments?teamId=…&forceNew=1` body `{name,deploymentId,target:'production'}`.
The env-var upsert alone does NOT trigger a rebuild — the first deploy after the
push still had the old env and served the app normally until forced.

{type:magiclink,email} → `hashed_token` → `POST /auth/v1/verify`
{type:magiclink,token_hash} with the **anon** key → `access_token`. Use it to

so a dummy URL bakes in and `fetch` fails with ENOTFOUND).
