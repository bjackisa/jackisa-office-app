The office app had **10 /api routes** reading/writing with the service-role

### REGRESSION FIXED: report cards / transcripts stopped sending
**Symptom:** "sending of academic transcript is not working any more" — the grades
screen said "Could not send the report card", and `document_deliveries` showed
`status=failed, error="Unexpected end of JSON input"` for every attempt.
**Root cause:** the hub `DocumentService::store()` returns the raw PDF under
`'pdf' => $pdf` (needed so `deliver()` can attach it). `EducationController::transcript`
and `::notifyMarks` returned the whole `$doc` through `Response::ok()`. Raw PDF bytes
are not valid UTF-8, so **`json_encode()` returned false → HTTP 200 with a 0-byte
body** (content-length: 0). The office `call()` does `res.json()` and throws
"Unexpected end of JSON input". The `'pdf' => $pdf` key was only added when the PDF
redesign landed — hence "not working any more".
**Fix (hub, deployed):**
- `EducationController::publicDoc()` returns only id/url/path/bytes/kind/title/sha256.
- `Response::emit()` now logs + returns HTTP 500 `response_encode_failed: <msg>` when
  `json_encode` fails, instead of silently emitting an empty body.
- Also send/print the human student number: office route sends `student_no`
  (`students.student_id`), hub `student()` reads `student_no`/`student_number`,
  `transcriptHtml` prefers it over the record id.
**Verified live:** POST `/api/v1/education/transcript` (HMAC) for Pervin Tusiime Ritah
(Jolis Academy) → `delivery.whatsapp[0].status = "sent"`, PDF shows "Student No.
S-1K0MT4S1" and the PLATINUM MONTHLY footer. General lesson: **never put raw binary
(bytes) in an API payload** — a silent `json_encode` failure yields a 200 with no body.

### WhatsApp: numbers not on WhatsApp now relay to the company
**Symptom:** report card sent, `message_log` said `sent`, but the parent never got
it. User: "didn't receive any whatsapp on her end".
**Root cause:** the number `256748004487` (Pervin, Jolis Academy) is **not
registered on WhatsApp**. Whapi accepts any send and returns `sent: true`; the
message then sits at status `pending` forever and is never delivered. The app
trusted `sent: true`, so a dead number looked like a success.
**Whapi API facts (verified live):**
- Check numbers: `POST /contacts` with `{"contacts":["256..."]}` → each result
  `status: valid|invalid`, valid ones add `wa_id`. Nothing is sent to the contact.
- Message status: `GET /messages/{id}` → `status: pending|sent|delivered|read|failed`.
- `GET /contacts/{number}` is *not* the check (404s for unsaved contacts); use POST /contacts.
- Health: `GET /health` → `status.code:4` means AUTH OK; `user.id` is the channel number.
- **Live proof:** `256748004487` → invalid (pending forever); `256742459007`
  (Jolis Academy) and `256701905782` (Mama Arthur) → valid.
**Fix (hub, deployed + committed 53c122a):**
- `WhatsAppService::isOnWhatsApp()` (POST /contacts), `messageStatus()` (GET
  /messages/{id}), `reconcile()`, and `sendWithFallback()`.
- `EducationController::deliver()` passes `company_phone` as the fallback; a number
  that is not on WhatsApp is logged `failed` ("Recipient is not on WhatsApp") and
  the notice (naming the student + the bad number) is relayed to the company number.
- `message_log.status` is ENUM('queued','sent','failed') — **do not** write other
  values (e.g. 'undeliverable'); they silently store as ''.
- Office route sends `company_phone` and reports `undeliverable` WhatsApp results,
  but still counts a successful email as delivered (commit a506ebe).
**Company numbers:** Jolis Academy = **256742459007** (companies.phone). Companies

## Document redesign v2 — matched to the user's HTML design system

The user supplied a full HTML design system (three templates sharing one look).
It is now implemented faithfully in `DocumentService.php`. Key facts:

### The design language
- **Ink spine + brass hairline** on the left edge of every page; serif display
  (Source Serif 4) over a sans body (Public Sans); status always **text + colour**.
- Tokens: ink `#12264A`, brass `#A9822F`, text `#1B2433`, muted `#5B6678`,
  line `#DCE1E9`, wash `#F3F5F9`. Status: pass `#17795A/#E3F3EC`,
  retake `#8F5A00/#FBF0DA`, fail/due `#B3261E/#FBE6E4`.
- CSS px map 1:1 to PDF pt (no DPI scaling), so the design's spacing carries over.

### Dompdf gotchas found by testing (all confirmed on the live host)
- **`* { margin:0 }` wipes the `@page` margin.** This was the big one — the whole
  document rendered at x0. Fix: `* { box-sizing:border-box }` plus a targeted
  `p,h1,h2,h3,table,tr,td,th,div,span,small,b,i,strong { margin:0;padding:0 }`.
- **No flexbox/grid, no pseudo-elements, no `::before`.** Structure = tables.
- **`position:fixed` repeats on every page** (Dompdf treats it as a running
  element). To full-bleed the spine past the `@page` margin, offset it
  **negatively**: `top:-40px;bottom:-30px;left:-56px` (match the @page margins).
- **Gradients do not paint**; use a solid div (plus a second 2px div for brass).
- **Progress bars**: an empty `<div>` with a height collapses. Use a
  `<table class="bar"><tr><td class="fill" style="width:80%">…` two-cell table.
- Fonts: Dompdf writes `<hash>.ufm` next to the font file, so **fontDir must be
  writable**. The bundled `vendor/.../lib/fonts` is not writable by PHP-FPM.
  `PdfService::prepareFontDir()` now points Dompdf at `storage/fonts`, seeds it
  with the package's own metrics (or the fallback families vanish), and registers
  the brand TTFs. Variable fonts were instanced to static weights with fontTools.
  See `PdfService::registerBrandFonts()` / `fontsDir()` (config `pdf.fonts_dir`).
- `@page` margin shorthand (`margin:40px 48px 30px 56px`) works; px→pt is 1:1.

### Files
- Hub: `src/Service/DocumentService.php` (shell + transcript + marks + generic),
  `src/Service/PdfService.php` (font registration), `storage/fonts/*.ttf` (brand
  fonts, committed with OFL.txt), `config/config.example.php` (`pdf.fonts_dir`).
- Office: `lib/notify/templates.ts` (invoice status_tone `due`, labels
  "Billed from"/"Bill to").
- Preview harness on the host: `/tmp/preview.php` → `storage/preview/*.{html,pdf}`;
  public gallery **https://lic.jackisa.com/preview/index.html**.

### Result
- transcript / marks / invoice all render **1 page**, content x42..559pt (A4
  with 48/48/40/56pt margins), spine+brass full bleed on every page, brand fonts
  embedded (PublicSans / SourceSerif4).

### Follow-up: Times fallback fixed
The notice's `/ max` divider fell back to Times because Source Serif 4 had no
**400** face registered (only 500/600/700). Dompdf maps 400→normal, so it asked
for a face that did not exist and substituted Times. Added
`SourceSerif4-Regular.ttf` (instanced from the variable font at wght 400/opsz 24)
and pinned `.score .of` to `font-weight:500` to match the design. All three
documents now embed only PublicSans / SourceSerif4 faces.

### Pushing to GitHub from this sandbox
`git push origin main` (and `git fetch`) **hang on a password prompt** — the
remote URL carries a stale embedded token. Push with the live token explicitly:
`git push "https://x-access-token:${GITHUB_TOKEN}@github.com/bjackisa/<repo>.git" main`,
then `git remote set-url origin` to the same URL so later fetches work. Verify a
push landed with the GitHub API (`/repos/bjackisa/<repo>/commits/main`), not with
`git fetch`, if the remote URL is still stale.

### Report card grades must equal the Grades screen (module totals)
The transcript was re-weighting **percentages** (`cw% × 0.5 + exam% × 0.5`)
while the Grades screen (`app/app/education/grades/page.tsx`) scales each half
to **50 points** and sums them. That rounding difference made every final grade
read low/false (e.g. Pervin MOD-2026-0001: screen 48.8 + 34.0 = **82.8**, card
showed 74.4). The Grades screen is the reference — match it exactly.
- Contract: `coursework = round1(min(raw/max × 50, 50))`, `exam = round1(exam/100 × 50)`
  or **null when the paper was not sat** (`--`), `total = coursework + exam`.
  A module with no marks recorded totals **0** (Fail) — that is the screen's
  behaviour, not "not assessed". Exams are always marked out of 100
  (`final_exams.max_marks = 100`).
- Grade letters (screen): A ≥80, B ≥70, C ≥60, D ≥50, E ≥40, F below. Hub
  `DocumentService::grade()` and office `gradeFor()` now agree.
- `lib/education/standings.ts` carries the halves directly; the hub
  `transcriptHtml` renders them as-is (no re-weighting) and derives the letter,
  average and overall band from the module totals, so summary == table.
- Verified 8/8 against the real Grades screen rows (module `0/0` divide guard
  included) with `node --experimental-strip-types`.
- Long transcripts are fine at **2 pages** (user's call) as long as the break is
  clean; `.table .code { white-space: nowrap }` stops `MOD-2026-000N` wrapping.
