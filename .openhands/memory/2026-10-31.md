
## Oct 31 2026 — security hardening + licence/trial audit

### API auth audit (fixed)
The office app had **10 /api routes** reading/writing with the service-role
client and **no caller check**, plus a client-only feature gate. Fixed in commit
"fix(security): authenticate every data route, gate modules server-side".

New helpers:
- `lib/lic/serverAuth.ts`: `getSession()` (caller + raw bearer), `requireMember()`
  (any active member), alongside existing `getCaller/requireCompanyAdmin/requireSuperAdmin`.
- `lib/lic/guard.ts`: `requireFeature(req, companyId, slug)` — server-side mirror of
  the client `can()` gate (tier + company kind/override + role grant). Loads
  `platform_features` catalogue and registers it before checking.
- `lib/api.ts`: `apiFetch()` / `apiJson()` — attaches the Supabase access token.
  **Every client call to a data route must use this, not raw fetch.**

Routes now guarded: `lic/license` (admin for issue/renew/change, member for
status/validate/change-quote), `lic/payments` (admin initiate, member status/history),
`jackisa` (admin POST, member GET), `payments/initiate` (member, body userId ignored),
`payments/status` (member of the payment's company), `payments/webhook` (HMAC sig via
`PAYMENTS_WEBHOOK_SECRET` or lic peer sig), `trial` (member; start/status/cancel),
`kyc` (GET requires caller; auto_individual now binds badge to the caller and matches
the jackisa.com email), `education/notify` + `education/student` + `reports/income-tax*`
(feature-gated), `lic/sync` GET (lic sig or `CRON_SECRET`).

Key lesson: **never trust `userId`/`initiatedBy`/`companyId` from the request body.**
`kyc auto_individual` used to mint a blue badge for any user id supplied by the client.

## Ledger / unit-trust / legacy backfill (later same day)
- **The "half-implemented ledger" was a one-way street.** `process_contribution`,
  `process_redemption` and `process_sale_to_fund_allocation` moved `cash_pool` and
  wrote `fund_transactions`, but never posted a double-entry journal, so
  `ledger_entries` never reflected fund money. `office-unit-trust-ledger-v2.sql`
  `CREATE OR REPLACE`s all three to post balanced journals via `jo_post_ledger_entry`
  (only the **net** enters the pool; gross clears through fee/WHT payables), and adds
  `jo_distribute_dividend` (clears `2500 Dividends Payable`, writes `dividend_allocations`).
  Function signatures must stay byte-identical to `investment-module-and-ecosystem.sql`
  or `CREATE OR REPLACE` errors ("cannot change name of input parameter").
- **`dividends` had no `updated_at`**, but `sync_dividend_financials` (fired by the
  `dividend_payments` trigger) writes it — so *every* dividend payment insert failed
  with `column "updated_at" of relation "dividends" does not exist`. Added
  `paid_amount/outstanding_amount/updated_at` in `office-ledger-trust-hardening-v1.sql`.
- **Ordering trap:** `industry-education-and-documents-v1.sql` and
  `payroll-ledger-and-trust-v1.sql` call `jo_is_company_member()`, which only
  `licensing-and-platform-v1.sql` defines. Apply `licensing-and-platform-v1.sql`
  **before** those two. The whole set is captured in `scripts/apply-office-sql.sh`
  (needs `SUPABASE_DB_URL`; office has no direct DB connection — Supabase REST only).
- `office-backfill-legacy-v1.sql`: chart of accounts per company, employer NSSF 10%
  on legacy payroll, fund/payroll/dividend ledger entries, default role, workspace
  fund, one `is_current` platform licence, trial mirror, owner→employee link.
- **Hub had licences but `subscriptions = 0`** (seeded/exercised before subscription
  writes existed) and several live licences per tenant. `lic-backend/migrations/006_backfill_legacy.sql`
  derives one subscription per tenant from its newest licence, keeps only the newest
  live licence, expires lapsed trials / converts those behind a live licence, and
  fills missing `grace_until`. Applied live: `php bin/migrate.php` → subscriptions 2.
- Validation harness: throwaway Postgres (`licpg`) + MariaDB (`licmy`) containers.
  Postgres needs Supabase shims (`anon/authenticated/service_role`, `auth.uid()`,
  schema `auth`) or the RLS/grant scripts abort. MariaDB needs `mariadb db < file`
  (the `\i` psql meta-command is not understood).

## Session 4 — "Education missing on Platinum" root cause (company kinds)
- **Symptom**: a workspace on a Platinum trial saw no Education modules.
- **Cause**: the feature gate binds some features to organisation *kinds*
  (`FEATURE_KINDS` in `lib/lic/features.ts`): education/students/coursework ->
  `['institution','ngo']`. The workspace (Jolis Academy) was created before
  company kinds existed, so `companies.kind` is the generic `'company'` while
  `companies.industry` correctly says `Education` (`industry_slug='education'`).
  The gate matched only the stored kind, so education was hidden even though
  Platinum unlocks it by tier.
- **Fix**: `hasFeature` now matches a feature's bound kinds against the stored
  kind **or** the kind implied by the company's industry (`profileFor(industry).kind`
  from `lib/industries.ts`). Wired through both the client gate
  (`lib/lic/useLicense.tsx` -> `can()`) and the server guard
  (`lib/lic/guard.ts` -> `requireFeature`). A plain business stays blocked.
  Committed `581f4f3`, pushed; Vercel deploy verified (chunk contains `industryKind`).
- **Related finding (not yet fixed)**: every `company_role_features` row is
  empty for Jolis (0 grants on all 15 roles). `isAdminRole` is a regex on
  role name/position (`admin|owner|director|manager|principal`), so
  "Office Administrator"/"Director" get everything in-tier but every other
  role (Technician, Security, Instructor, ...) falls back to the basic surface.
  Fine for the owner; worth a proper role->feature matrix screen later.
- **Company kind is user-editable** at `/app/settings/company` ("Organisation
  type"); the industry select on `/auth/register` already auto-sets the kind.
